CVE Shield is available for this CVE and supports BLOCK mode, but every environment is set to MONITOR. The attack was detected, not stopped.

Why this CVE matters

Risk context from get_cve_impact

Apache Log4j2 JNDI features do not protect against attacker-controlled LDAP and other JNDI endpoints. An attacker who controls a log message or its parameters can load and execute code from a remote server when message lookup substitution is enabled. The CVSS vector is CVSS:3.1/AV:N/AC:L/PR:N/UI:N/S:C/C:H/I:H/A:H, which means network reachable, low complexity, no privileges and no user interaction.

Contrast flags it as Known Exploited and the EPSS percentile of 100 puts it among the most likely CVEs to be exploited in the wild.

Recommended response

Ordered by speed to reduce risk

  1. Contain. Switch CVE Shield for CVE-2021-44228 from MONITOR to BLOCK in QA and production.
  2. Investigate. Review the observations on ISS-2026-1473 to see what the attacker sent and whether code executed.
  3. Fix. Upgrade log4j-core from 2.14.1 to a release that removes the JNDI lookup behavior, 2.17.1 or later on Java 8 and above.
  4. Verify. Re-run this report after deployment and confirm the issue closes and the shield status clears.
