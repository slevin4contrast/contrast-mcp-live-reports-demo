📝 Report Generation Prompts

Behind the Scenes: The AI Prompts That Generated These Reports

About This Documentation

This page documents the exact prompts used to generate each report in this repository. These prompts were given to Claude (via Claude Code) which interfaced with the Contrast MCP Server to retrieve security data and create interactive visualizations.

Each report generation typically involves multiple steps: data retrieval, processing, visualization, and deployment. The prompts below show the complete workflow from request to final output.

🗺️ Attack Map Visualization

Generated: January 17, 2026 | File: attack_map.html

1 Data Retrieval Prompt

🔍 MCP Tool: search_attacks 📊 Data Source: contrastmcp-eval-cargo-cats
Purpose: Retrieve attack data from Contrast ADR (Attack Detection and Response) and compile a list of source IP addresses.
USER PROMPT get me the attack data for each and supply me a list of ip addresses from which the attacks came from

📤 Output Generated:

  • 8 total attacks identified (1 exploited, 7 probed)
  • 6 unique source IP addresses extracted
  • Attack details including rules triggered, probe counts, severity levels
  • Affected applications and timeframes

2 Visualization Generation Prompt

🎨 Output: HTML/CSS/JavaScript 🗺️ Library: Leaflet.js 🌐 Server: Python HTTP
Purpose: Create an interactive geographic visualization showing attack sources, connection lines to the server, and detailed hover information.
USER PROMPT using these ip addresses, look up where they came from geographically, and then create an html page, host it in a python server, open a browser to show it, but have a map of the US, pinpoint on the map where they came from and have connecting lines showing them attacking the server which is hosted in northeast indiana. make it so when hovering over the lines, it shows what kind of attack it is and whether or not it was exploited.

📤 Output Generated:

  • Interactive map using Leaflet.js with dark theme
  • Server marker in Fort Wayne, Indiana (Northeast Indiana)
  • 6 attack source markers with color coding (red = exploited, orange = probed)
  • Animated connection lines showing attack vectors
  • Hover tooltips displaying attack details (IP, rules, status, probes)
  • Legend explaining visualization elements
  • Python HTTP server launched on port 8000
  • Automatic browser launch to display the map

Generation Workflow

1. User Request → 2. Query Contrast MCP → 3. Process Attack Data → 4. Generate HTML/JS → 5. Launch Server → 6. Display Result

⚡ Live Data Conversion

Generated: October 21, 2026 | Files: server.js, lib/mcp.js

1 Turning Static Reports Into Live Dashboards

🔍 MCP Tools: search_vulnerabilities, search_applications, get_route_coverage 🔌 Runtime: Node.js proxy calling the MCP server 🔐 Auth: existing MCP OAuth token, server-side only
Purpose: Replace hardcoded numbers with data fetched at page load, so a demo always reflects the current state of the org rather than a snapshot.
USER PROMPT can we make them live dynamic pages with api calls to my eval org?

📤 Output Generated:

  • Dependency-free Node server bound to localhost, calling the same MCP tools Claude Code calls
  • No second API client and no new credentials, since the server reuses the MCP OAuth token already in the keychain
  • Mock mode with fixtures, so the demo still runs with no token and labels itself MOCK DATA
  • LIVE or MOCK badge, last-refreshed timestamp, and a Refresh button on every converted page
  • Error banner that falls back to the static snapshot when the API is unreachable
  • Original pages preserved as *_static.html for offline demos
  • Six pages converted: vulnerability dashboard, route coverage, library security, a CVE explorer with a picker, attack activity, and the compliance dashboard
  • Two pages had to drop invented content: the attack map plotted private 10.x addresses on US cities, and the compliance dashboard reported an MTTR for an org with zero remediated findings
  • Live data revealed drift from the snapshots at every turn: 27 findings rather than 24, route coverage at 46% rather than 60.77%, and 420 libraries rather than 127

💡 Key Insights

Prompt Engineering: The prompts demonstrate natural language interaction with the MCP server. No complex API calls or SQL queries were needed - just conversational requests.

MCP Integration: The Contrast MCP Server seamlessly provides security data through standardized tool interfaces, enabling AI to generate comprehensive security reports and visualizations.

Multi-Step Workflows: Complex outputs like the attack map required multiple prompts - first to retrieve data, then to create the visualization. This modular approach allows for flexible, iterative development.
